# 중단 없는 전집 제작 규약

## 1. 목적과 순서

유일한 목적은 EGA, FGA, SGA, AI Commons Stacks의 한국어판을 이 순서대로 전부 완성하는 것이다. 이 목적에는 원문과 동기화된 편집 가능한 TeX, 재현 가능한 PDF 빌드, 구조 색인, 용어 기록, 추출 검사, 렌더 검사가 포함된다. 시범 번역, 표본 번역, 몇 쪽짜리 승인 단계는 없다. 닫힌 절·정의·명제·증명 단위는 단지 다음 문장으로 안전하게 이어 가기 위한 체크포인트이며 전체 범위를 줄이지 않는다. 사람의 사전 승인이나 미래 검토 가능성, 토큰 비용은 중지 조건이 아니다. 사용자가 자원을 다른 곳에 배정하여 직접 일시정지할 때만 멈춘다.

## 2. 압축은 파괴로 취급한다

세션 요약·압축·전사는 상태가 아니며 증거도 아니다. 압축 뒤에는 그것을 읽고 믿지 않는다. 다음의 원본만으로 상태를 재구성한다: `raw/`의 사용자 원문, `state.json`, `cursor.json`, `authority.json`, 추가 전용 JSONL 기록, 현재 TeX/PDF의 실제 바이트와 SHA-256, 빌드·렌더 영수증. 재진입 순서는 고정이다. (1) 최신 원문 지시를 읽는다. (2) 현재 상태와 정확한 커서를 읽는다. (3) 커서가 가리키는 원문 파일·범위·해시를 다시 계산한다. (4) 직전 목표 파일과 빌드 영수증을 다시 계산한다. (5) 일치하면 다음 문장부터 번역한다. 불일치할 때만 `hard.jsonl`에 차이를 기록하고 마지막 일치 경계에서 복구한다. 요약을 근거로 이미 끝난 내용을 재번역하지 않는다.

## 3. 한 방향 생산 루프

각 단위에는 단 한 번 다음 절차를 적용한다. 정확한 원문 범위와 해시를 고정하고, 수식·식별자·라벨·인용키·교차참조를 보존하면서 한국어 산문을 번역하고, 목표 TeX를 저장하고, 구조 대응을 추가하고, 누적판을 빌드하고, 추출과 바뀐 페이지만 검사하고, 기록을 추가한 다음 커서를 정확히 한 번 전진시킨다. 완료 단위는 원문 해시 변경 또는 위치가 특정된 결함이 없으면 다시 감사하지 않는다. 전집 전체의 상태표를 매 단위마다 재작성하지 않는다. 기존 목록과 해시를 반복 검증하는 데 생산 시간을 쓰지 않는다.

## 4. 원문 권위와 변경

다른 소유자의 원문 파일은 읽기 전용이다. 한국어 목표 파일은 이 루트만 쓴다. EGA의 현재 NUMDAM 기반 프랑스어 TeX를 주권 원문으로 삼고 영어판은 오직 의미 확인용 증인으로 사용한다. 원문 소유자가 파일을 바꾸면 현재 커서보다 앞선 부분에 실제 바이트 차이가 있는지 한 번 계산하고, 영향을 받은 한국어 범위만 재기반화한다. 나머지는 그대로 유지한다. 원문 오류로 보이는 항목은 정확한 파일·행·바이트·해시·관찰·대안을 `hard.jsonl`에 기록하되 번역을 멈추지 않는다. 외부 작업에 메시지를 보내거나 원문을 직접 고치지 않는다.

## 5. 한국어 편집 규칙

대한민국 표준을 기본으로 하고 한글을 본문 기본 문자로 쓴다. 의미 충돌 가능성이 있을 때 첫 등장에 한자·프랑스어·영어를 최소한으로 병기한다. 북한 표준이 실질적으로 다른 경우에만 별도 기록한다. 중국어·일본어 용어는 한국어 권위가 아니다. 각 새 핵심어는 뜻 범위, 채택어, 거부안, 근거, 불확실성, 어휘 유인 분지를 `terms.jsonl`에 한 번 기록한다. 원문의 길고 조밀한 문체를 임의로 단순화하거나 설명을 추가하지 않는다. 수학적 내용과 논증 순서를 그대로 유지하면서 자연스러운 전문 한국어로 옮긴다.

## 6. 실패 처리

같은 실패를 반복 실행하지 않는다. 첫 실패에서는 직접 원인을 읽고, 둘째 시도에서는 원인에 한정된 수정만 하고, 셋째에도 같은 장애가 남으면 실패 증거·재현 명령·잔여 위험을 기록한 뒤 번역 가능한 다음 닫힌 단위로 계속 간다. 대규모 재빌드와 전체 렌더는 필요한 경계에서만 한다. 평소에는 누적 TeX를 빌드하되 바뀐 쪽만 시각 검사한다. 임시 산출물은 `qa/tmp`에 두고 영수증 확정 뒤 제거한다.

## 7. 상태와 인계

모든 결정과 실패는 덮어쓰지 않고 추가한다. `state.json`과 `cursor.json`만 현재 포인터이므로 원자적으로 갱신할 수 있다. 파일명과 디렉터리는 짧게 유지하고 상세 이력은 파일 내용에 둔다. 각 작업 턴은 실질 번역을 남기고 끝난다. 최종 응답은 완료한 실제 범위, 정확한 파일, 해시, 빌드·렌더 결과, 다음 커서만 짧게 밝힌다. 외부 출판, Zenodo, GitHub 변경은 별도 사용자 허가가 있기 전에는 하지 않는다. Lean 파일·빌드·형식화·색인은 어떤 경우에도 만들거나 실행하지 않는다.
